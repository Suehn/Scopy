# v0.78.0 Release Performance Profile

## Scope

Interaction latency outside scrolling: hover preview, search typing, clipboard capture, launch, page loads. Every number comes from real input against the real panel and the real 9,566-row snapshot database on a Release build.

## Environment

- Date: 2026-09-03
- Host: Apple M3 Pro (5P+6E), 36GB, 120 Hz; macOS 15.7.3 (`24G419`); Xcode 26.1.1 (`17B100`)
- Drivers: `scripts/perf-scroll/profile_scroll.py`, `profile_search.py`, `profile_capture.py`; hover timeline from `ScopyLog.ui` "Hover preview" stages driven by real mouse-moved events; main-thread attribution with `sample`

## Hover preview (Markdown text items, 8-14 KB, delay 1.0 s, preview scale 125% vs Settings 100%)

| Stage | Before | After |
| --- | ---: | ---: |
| Work starts | at 1,065 ms (delay elapsed) | at 320 ms (prefetch) |
| HTML ready | 1,139 ms | 345-360 ms |
| WebView navigations per hover | 2 (first at 0 px width) | 1 offscreen at 640 px (cold), 0 (warm) |
| Popover final size | after two resizes, 1,327-1,347 ms | first frame, 1,042-1,045 ms |
| Terminal render on screen | 1,327-1,347 ms | 1,083-1,134 ms |

Root causes removed: the pipeline rendered at the Settings scale while the popover displayed the preview-local scale (second render + navigation per hover); the popover measurement pass navigated the WebView at zero width; nothing started before the delay.

## Search typing (`clipboard hist`, 14 keys at 8/s)

| Metric | Before | After |
| --- | ---: | ---: |
| List body evaluations | 56 | 31 |
| `HistoryItemView.init` calls | 541 | 486 |
| Rows on screen between keystrokes | emptied on every key | kept |
| Main-thread busy (4 s window) | 17.5% | 18.3% |

The `onChange(of:)` observers on `isLoading`, `loadedCount`, `totalCount`, `canLoadMore`, `itemsRevision`, `searchMatchContexts.count` and the reconciliation token in `HistoryListView.body` made every flag change rebuild the list; they now live in `HistoryListStateObservers`. Remaining per-keystroke cost is result-row layout.

## Clipboard capture (three 1.2 MB RTF+HTML copies, plus RTF-only, HTML-only, 1 MB plain text)

| Metric | Before | After |
| --- | ---: | ---: |
| Main-thread samples in extraction | 5,456 (58.5%) | 31 (0.3%) |
| Main thread idle during the run | 37.9% | 90.2% |
| Per-copy main-thread block (logged) | 1,909-2,386 ms | none; 660-670 ms of background processing |

Microbenchmark on the same 1 MB document: RTF import 9 ms (thread-safe), WebKit HTML import 315-697 ms (main-thread-only), normalization 53 ms per pass. The HTML import is skipped when `preferredPlainText` cannot pick its text (non-empty pasteboard string, not authored Markdown, no `\`/`$` or entity that could decode to them in the HTML or the string).

## Preview image cache

`HoverPreviewImageCache` per-entry cap 96 -> 256 MB and total cost 160 -> 320 MB. The decode budget stays at 64 Mpx (a 24 Mpx budget was tried and rejected: it scaled a 2000x100000 screenshot to 0.54x, failing the policy's own sharpness tests), so the cache now holds what the policy decodes and a tall screenshot is decoded once per 60 s TTL instead of on every hover.
