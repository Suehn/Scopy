# v0.80.1 Search Pagination Profile

Three interleaved A/B pairs reduce the median of each run's longest active animation callback from **91.7 ms to 58.3 ms** (36.4% shorter, a 1.57x ratio). Median Scopy CPU time is **3.76 s to 3.65 s** (2.9% lower). Callback p95 remains 8.33 ms. This supports a reduction in pagination stalls, not an application-wide 1.5–2x speedup or a presented-frame-rate claim.

## Scope And Method

- Baseline: clean `212b817`; candidate: `777e911` (search fix `78c4232` plus the independently verified cleanup merged to main). Both are Release configuration, running natively on arm64; baseline bundle is universal and the local candidate build uses ONLY_ACTIVE_ARCH.
- Apple M3 Pro, 36 GB; macOS 15.7.3 (24G419); Xcode 26.1.1 (17B100). Project deployment/language baselines are unchanged.
- Fresh 9,756-row database snapshot, 480 x 640 panel, Fuzzy query `the`. Same warm snapshot copy, 720 pixel-wheel CGEvents at 60 Hz over 12 seconds, delta 24 px, direction reversed every 4 seconds. Pointer parked outside the list during settle and immediately after the gesture. Ordering: baseline/current, current/baseline, baseline/current.
- All six runs loaded 250 rows, reported 250 match-evidence entries and search_ready=true, and recorded 680–714 moving callbacks. The identical gesture does not guarantee identical row traversal; list insertions and pinned sections can compensate scroll position.
- CPU is external process sampling during the 12-second gesture. App callback/runloop instrumentation spans approximately 24 seconds, including setup/settle. Do not equate those windows. A separate idle QA instance remained running during all six comparisons and was closed afterward; the same ambient condition applied to both variants.
- Adaptive expected-frame calibration varied between 8.33 and 16.67 ms; drop ratios are excluded from comparisons. No display-presented FPS was measured.
- Original uncommitted opaque-row experiments were excluded. No row content, transparency, button behavior, hover previews, pinned previews, or settings transactions were removed.

Reproduce each run with the matching build and a fresh `make snapshot-perf-db` copy (the live database changes, so preserve snapshot identity when reproducing this exact sample):

```bash
SCOPY_PROFILE_SEARCH_QUERY=the SCOPY_PROFILE_SEARCH_MODE=fuzzy \
  python3 scripts/perf-scroll/profile_scroll.py <app.app> <label> \
  --mode wheel --duration 12 --reuse-db --attempts 1
```
