# v0.65.3 Release Performance Profile

## Scope

This profile records the four waste-removal fixes shipped by `v0.65.3`: mutation-sequence disk-cache invalidation, typing-safe interactive warm-up, the corpus-metrics expression index, and the history-list revision token. The causal claims are the real-database regression timings and the corpus-metrics query measurement; the backend audit and frontend profiles are regression guards recorded without speedup claims where movement is within run-to-run variance.

## Environment And Input

- Date: 2026-08-22
- Host: Apple M3 Pro, arm64
- macOS: 15.7.3 (`24G419`)
- Xcode: 26.1.1 (`17B100`)
- Configuration: Release for benchmarks; Debug for XCTest regressions
- Snapshot DB (same-day, real data): 9,566 items, 146,255,872 bytes, schema v8 at snapshot time, migrated to v9 by the current service during the audit
- Real-database regression input: isolated same-day copy of the live database (9,559 items at copy time)

## Comparison vs v0.65.2 (same host, same snapshot)

Backend service-layer P95 (30 iterations, 20 warm-up):

| Workload | v0.65.2 baseline | v0.65.3 current | Change |
| --- | ---: | ---: | ---: |
| service `cm` | 5.237ms | 5.246ms | +0.2% |
| service `数学` | 24.801ms | 24.379ms | -1.7% |
| service `cmd` | 0.565ms | 0.634ms | +12.2% (abs +0.069ms) |
| service `cm` no-thumbnails | 5.375ms | 4.763ms | -11.4% |
| Full-index warm load (cold build) | 234.7ms | 254.0ms | variance; see note |
| Peak RSS | 191.03MB | 155.03MB | -18.8% |

Engine-layer `cm` rows moved in the single audit run (`6.094ms -> 8.244ms`; forceFullFuzzy `7.402ms -> 12.109ms`), but an immediate re-run measured `5.100ms` and `5.209ms`, below baseline. The movement is run-to-run variance; the re-run additionally benefited from the now-valid v4 disk cache. The warm-load row measures a cold build from the database and is expected to be flat: this release's claim is cache validity across restarts, not a faster cold build.

## Causal Results

- **Cold-start refine with a valid disk cache** (`testFullIndexDiskCacheLoadsAndMatchesRebuild`, isolated real-database copy): rebuild refine `1789.7ms`; disk-cache refine `271.6ms` (6.6×) with identical result ordering. Before this release the cache was invalidated by the quit-time WAL checkpoint on effectively every restart, so the rebuild cost was paid at every cold start.
- **Typing-safe warm-up** (`testColdStartPrefilterWarmsFullIndexAndRefineMatchesOnDemandResults`): prefilter `2.3ms`; refine after prewarm `32.3ms`; cold no-prewarm refine `1903.2ms`. Previously every keystroke cancelled and restarted the warm-up build, so heavy corpora repeatedly paid the cold path.
- **Corpus metrics** (real database, `sqlite3` timer): `COUNT(*)+AVG+MAX(LENGTH(CAST(plain_text AS BLOB)))` full scan `268ms` -> index-only scan `<1ms` after `idx_plain_text_bytes`; identical results (9,559 / 2038.86 / 1,014,052). One-time index build on the 139MB database: `14ms` warm.
- **History-list revision token**: removes an O(loaded plain-text bytes) main-thread array comparison per items change; at the current ~500-1500 loaded items this is a `1-3ms`-per-event saving that scales linearly with loaded history.

## Frontend Profiles

- Standard profile (three scenarios improved, one flat): frame p95 `-34.8%` accessibility, `-38.1%` mixed, `-90.9%` search-evidence, `0.0%` text-bias; row-body p95 down in all four scenarios. Baseline/current compare runtime feature-flag variants within the same revision and are regression observations, not causal claims for this release.
- Full profile (three repeats of 10 seconds): frame p95 flat at `0.00%` in mixed, search-evidence, and text-bias; accessibility moved one 8.333ms frame bucket (`33.333ms -> 41.667ms`) with long-frame attribution dominated by `19.2s` of cold thumbnail decodes in that variant, outside this release's paths. Row-body p95 decreased in all four scenarios (`-7.8%`, `-2.2%`, `-2.0%`, `-0.6%`).

## Test Coverage Changes

- Added `testFileChurnWithoutMutationDoesNotInvalidateFullIndexDiskCache`: WAL checkpoint plus file-attribute drift on all three DB files must not invalidate a logically unchanged cache.
- Added `FullIndexWarmupContinuityTests.testTypingDifferentQueriesKeepsOneInteractiveWarmupBuild`: consecutive different fuzzy queries must reuse one in-flight warm-up build (asserted via the build-generation counter).
- Replaced `testSHMDriftDoesNotInvalidateFullIndexDiskCache` (file-fingerprint concern removed with the mechanism).
- Migration test now asserts the terminal `user_version` from `SQLiteMigrations.currentUserVersion` instead of a hardcoded constant.

## Regressions

None identified. All snapshot Release SLOs hold with large margins (`cmd p95 0.612ms / 50ms`, `cm p95 5.352ms / 20ms`); service-level audit movement is within noise; unit, strict-concurrency, and real-database suites pass with 0 failures.
