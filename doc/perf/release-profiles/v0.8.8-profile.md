## Bottleneck Attribution

The pre-change profile identified two non-thumbnail scroll bottlenecks:

| Scenario | Row display-model overlap | Markdown-detect overlap |
|---|---:|---:|
| real-snapshot-accessibility | 1060.10ms | 729.12ms |
| real-snapshot-mixed | 994.42ms | 673.54ms |
| real-snapshot-text-bias | 774.71ms | 530.42ms |

Thumbnail decode also remained visible in image-heavy scenarios, but thumbnail work was deliberately deferred.

## Post-change Smoke Result

| Scenario | Pre frame p95 | Post frame p95 | Pre drop ratio | Post drop ratio | Pre long frames | Post long frames |
|---|---:|---:|---:|---:|---:|---:|

| real-snapshot-text-bias | 58.333ms | 16.667ms | 0.261 | 0.000 | 213 | 0 |

Post-change `text.markdown_detect_ms` did not appear in long-frame attribution for any real-snapshot scenario.

## Release Caveat

`perf-frontend-profile-standard` was not refreshed before the tag because the macOS session was locked during the release cutover. Xcode's UI recording showed the lock screen, which prevents a valid Scopy foreground window and invalidates standard UI profile sampling. The user requested publishing first and rerunning the standard profile after returning to unlock the machine.
