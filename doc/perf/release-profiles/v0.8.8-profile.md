## Bottleneck Attribution

The pre-change profile identified two non-thumbnail scroll bottlenecks:

| Scenario | Row display-model overlap | Markdown-detect overlap |
|---|---:|---:|
| real-snapshot-accessibility | 1060.10ms | 729.12ms |
| real-snapshot-mixed | 994.42ms | 673.54ms |
| real-snapshot-text-bias | 774.71ms | 530.42ms |

Thumbnail decode also remained visible in image-heavy scenarios, but thumbnail work was deliberately deferred.

## Post-unlock Full Result

After the macOS session was unlocked, `make perf-frontend-profile-full` completed with 18 raw JSON profile outputs: 3 repeats x 3 real snapshot scenarios x baseline/current.

| Scenario | Frame p95 baseline | Frame p95 current | Drop ratio baseline | Drop ratio current | Main runloop p95 baseline | Main runloop p95 current |
|---|---:|---:|---:|---:|---:|---:|
| real-snapshot-accessibility | 16.667ms | 16.667ms | 0.204 | 0.141 | 7.611ms | 7.774ms |
| real-snapshot-mixed | 8.333ms | 8.333ms | 0.009 | 0.014 | 7.596ms | 7.753ms |
| real-snapshot-text-bias | 8.333ms | 8.333ms | 0.016 | 0.014 | 7.865ms | 7.663ms |

Key full-profile observations:

- `text.markdown_detect_ms` remains absent from real-snapshot scroll buckets.
- `row.display_model_ms.p95` remains small: `1.852ms` accessibility, `1.874ms` mixed, and `1.930ms` text-bias.
- `text.metadata_ms.p95` tracks the display model work: `1.848ms`, `1.872ms`, and `1.928ms`.
- `real-snapshot-accessibility` long frames fell from `837` to `392`, while drop ratio fell from `0.204` to `0.141`.
- `real-snapshot-text-bias` kept `8.333ms` frame p95 and reduced drop ratio from `0.016` to `0.014`.
- Remaining visible app-correlated cost is thumbnail decode/load in image-bearing paths; thumbnail scheduling was intentionally deferred for a separate optimization.

## Release Caveat Status

`perf-frontend-profile-standard` was not refreshed before the tag because the macOS session was locked during the release cutover. Xcode's UI recording showed the lock screen, which prevents a valid Scopy foreground window and invalidates standard UI profile sampling. The user requested publishing first and rerunning the standard profile after returning to unlock the machine.

That caveat is now resolved by the post-unlock standard, full, and include-hover profiles listed above. The profile harness now defaults to the XCUI list path again and exposes `SCOPY_PROFILE_SKIP_AX_LIST_QUERY=1` only as an escape hatch for the app-side automated scroll path. It also retries once when Xcode/XCUI completes a test run without writing the expected profile JSON.
