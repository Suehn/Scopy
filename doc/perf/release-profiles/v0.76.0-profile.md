# v0.76.0 Release Performance Profile

## Scope

First scroll profile taken with real scroll-wheel input against the real history panel and the real snapshot database on a Release build, attributed with a main-thread `sample` call tree instead of the app's callback-interval buckets. It records why earlier row-level optimizations could not move the user-visible number, and the three fixes this release ships.

## Environment And Input

- Date: 2026-09-02
- Host: Apple M3 Pro (5P+6E), 36GB, arm64, 120 Hz display; macOS 15.7.3 (`24G419`); Xcode 26.1.1 (`17B100`)
- Configuration: Release (`make release`), driven by `scripts/perf-scroll/profile_scroll.py`
- Snapshot DB: `perf-db/clipboard.db`, 9,566 rows (2,481 images), 146,255,872 bytes, copied per run
- Panel: the real `FloatingPanel` opened via `SCOPY_PROFILE_OPEN_PANEL=1`, default 480x640
- Pointer: the maintainer's system has an Accessibility pointer customization (`mouseDriverCursorSize` 2.35, custom fill/outline colors). This matters for the cursor finding below; users with the default pointer pay a much smaller version of that cost.
- Wheel workload: pixel scroll-wheel `CGEvent`s, 24 px at 60 Hz, direction flipped every 4 s, 12 s, cursor over the list
- Fixed workload: the app's display-link driver, 1440 commands of 36 px after 2 warm rounds (34,560 px observed path)

## Findings (baseline main thread, wheel workload, 9,895 samples)

| Share | Where | Cause |
| ---: | --- | --- |
| 22.8% | `-[_NSTrackingAreaAKManager setCursorForMouseLocation:]` -> `NSHostingView.cursorUpdate` -> `-[NSCursor set]` -> AccessibilityFoundation cursor regeneration (Gaussian blur, `SLSGetRegisteredCursorDataSize`) | AppKit re-evaluates the cursor on every display cycle in which tracking areas moved (every scroll frame); with the pointer customization each `set` regenerates the cursor image. Traced: ~70 calls/s, 2.95 ms each, 100% setting the cursor that was already current. |
| 11.2% | `ClipboardItemContentRevision.init(item:)` under `HistoryListView.historyRow` | Every ForEach child rebuild recomputed the SHA-256 cache key; the digest itself was negligible, the 32 `String(format: "%02x")` calls were not. |
| 8.7% | `installObservationSlow` under `ForEachChild.updateValue` | `historyRow(item:)` read `selectedID`, `settings`, `activePopover`, and `searchMatchContext(for:)` inside the per-row closure, so each child installed its own observation and copied the access list. |
| 10.1% / 9.1% / 7.5% | `NSHostingView.layout`, `NSTableView` row recycling, `scrollWheel` | SwiftUI List cell layout and AppKit table work per frame (unchanged). |
| 4.4% | `PointerRegionUpdater` | Per-row `.onHover` regions reinserted as cells recycle (unchanged). |

Removing the per-row `.onHover`, disabling window cursor rects, and stripping the hosting view's tracking areas were each tried and left the cursor share unchanged, which is why the fix intercepts the redundant `set` itself.

## Fixes

- `ScrollCursorSetCoalescer` (`Scopy/Runtime/ScrollCursorSetCoalescer.swift`): swaps `-[NSCursor set]` and drops a set of the cursor that is already current when the same cursor was set less than 100 ms ago. Traced during the wheel workload: 1,197 skipped, 3 performed.
- `ClipboardItemContentRevision.resolve(item:)`: memoizes the revision per item id (validated against every field that feeds it) and encodes the digest with a lookup table; the row view, presentation cache, and view model use it.
- `HistoryListView` captures `selectedID`, `settings`, `activePopover`, and the search-match dictionary once per list update into `HistoryRowContext` and passes values into the row builder.

## Results

Wheel workload (real input, 12 s, min of runs `wheel-baseline-3` vs `wheel-fix6-1`):

| Metric | Before | After |
| --- | ---: | ---: |
| Scopy CPU time during 12 s | `14.34 s` (119% of a core) | `9.76 s` (81%) |
| Active animation-callback interval p95 / max | `83.3 / 91.7 ms` | `16.7 / 25.0 ms` |
| Active callbacks over threshold | `13.1%` | `0%` |
| GPU utilization (avg) | `42%` | `19%` |
| `-[NSCursor set]` share of main thread | `21.4%` | `0.0%` |
| `ClipboardItemContentRevision` share | `11.2%` | `0.4%` |
| `installObservationSlow` share | `8.7%` | `0.2%` |
| Main thread idle (`__CFRunLoopServiceMachPort`) | `~0%` | `54%` |

Fixed workload (1440 commands, same path, `fixed-baseline-1` vs `fixed-fix6-1`):

| Metric | Before | After |
| --- | ---: | ---: |
| Main run-loop busy during the 12.0 s workload | `8,378 ms` (70%) | `3,931 ms` (33%) |
| Run-loop interval p95 / max | `7.11 / 12.0 ms` | `4.94 / 7.8 ms` |
| Scopy CPU time over the 30 s sampling window | `23.29 s` | `11.73 s` |

Remaining main-thread work after the fixes (fixed workload, share of samples): CA commit + AppKit layout 12.8% (`NSHostingView.layout` 4.4%), `NSTableView` row recycling 10.8%, `PointerRegionUpdater` 6.3%, AttributeGraph updates 15.3%, the profiling driver itself 11.9%.
