## Architecture Result

- Idle rows no longer create preview, note, Markdown export, or image-optimization controllers. One optional row interaction session owns them only while interaction or owned async work is active.
- List scroll coordination owns one active row and one tokenized suppressed-hover candidate instead of broadcasting scroll state to every visible row.
- Same-ID content replacement uses an explicit content revision across preview, note, export, optimization, presentation, and cache boundaries.
- Scrollbar suppression begins only when mouse-down hits an actionable vertical or horizontal scroller part and mouse-up matches the same pointer token.
- Presentation and relative-time caches are bounded and list time updates pause while scrolling or hidden.
- The Markdown context-menu fast signal is cached separately from exact PNG-export capability by content revision, including negative results; prewarm work is deduplicated, utility-priority, and generation-guarded.

## Deterministic Fixed A/B

The final harness ran five Release pairs in both AB and BA order. Every run completed automatically without manual pointer movement and used `NSScreen CADisplayLink` to drive the production `NSScrollView` target. Each side executed 1,440 commands of 36px across two warm top-bottom-top rounds; boundary clamping produced the same observed 51,270px path in all ten runs. Source, app executable, build artifacts, environment, and suite manifests were byte-identical across both axes and all twenty raw runs.

| Main run-loop whole-run total | 11,153.164ms | 10,732.824ms | -3.77% |

All five pairs improved row-body count (`-66.05%` to `-66.50%`), row-body total (`-60.55%` to `-61.52%`), and main-run-loop total (`-0.34%` to `-4.43%`). Main-run-loop p95 improved in four pairs; pair 2 was `+0.38%`, below the `+10%` guard. Passive runs reported zero row interaction sessions and zero row scroll observers; baseline medians were 1,150 of each over the workload.

## Trace-Selected Markdown Menu Signal Cache

After the passive-row result passed, an 8-second live `sample` was captured against the actual DerivedData Release app during the same 1,440-command workload. Of 457 samples in `HistoryItemView.body`, 418 entered context-menu construction and 411 entered `canOfferPNGExport`. The trace therefore selected the repeated `MarkdownDetector.hasFastMarkdownSignal` scan, not revision hashing or descriptor caching, as the next slice.

The follow-on keeps exact capability and the fast menu heuristic in separate caches. Exact cached `true` or `false` remains authoritative. The heuristic cache is keyed by `ClipboardItemContentRevision`, stores both outcomes, caps at 4,096 entries, prewarms on a detached utility task, deduplicates in-flight revisions, and rejects completion after a cache-generation change.

The formal same-binary comparison used `--axis markdown-menu-cache`: both variants kept passive rows enabled and only `SCOPY_PERF_MARKDOWN_MENU_SIGNAL_CACHE` changed. Five AB/BA pairs again completed 1,440 commands and the same 51,270px observed path in all ten runs.

## Real-Snapshot Regression Profile

The final `make perf-frontend-profile-standard` completed one 6-second baseline/current repeat across accessibility, mixed, and text-biased scenarios with at least 120 samples against the 7,807-row snapshot. Main-run-loop p95 changed `9.603ms -> 7.918ms` for accessibility (`-17.55%`), `9.720ms -> 8.374ms` for mixed (`-13.85%`), and `8.045ms -> 8.471ms` for text-biased (`+5.29%`). Row-body p95 changed `+7.34%`, `-4.13%`, and `-1.50%` respectively. Callback over-threshold ratios and thumbnail totals also moved in conflicting directions, including a text-biased thumbnail outlier, so this single-repeat composite is kept as a regression observation rather than a causal pass claim.

An earlier full profile completed three 10-second repeats per variant with at least 260 callback samples per scenario against the 7,794-row snapshot. Accessibility main-run-loop p95 improved `7.515ms -> 7.125ms` (`-5.19%`), mixed changed `7.003ms -> 7.224ms` (`+3.16%`), and text-biased changed `6.510ms -> 7.271ms` (`+11.69%`) at the independently aggregated medians. Text-biased pairwise p95 improved in repeats 1 and 2 (`-5.90%` and `-0.45%`) but regressed in repeat 3 (`+19.78%`); aggregate long-frame count moved `326 -> 258`, while callback over-threshold ratio moved `0.069 -> 0.119`. It predates only the final fixed-profile clock/tooling commits, so its product-path observation remains useful, but it is not presented as a final-source release gate. These conflicting signals are recorded as unresolved broad-profile variance.

The real-snapshot harness is also a composite feature-flag guard, not an old-revision comparison: its baseline disables history indexing, scroll-resolver caching, Markdown-resolver caching, preview task budgeting, and short-query debounce together, while both variants keep the new passive-row and Markdown menu-signal cache defaults enabled. It therefore cannot attribute the text-biased variance to either v0.65.0 slice. The fixed AB/BA workloads above remain the causal evidence for those slices. `animation_callback_source` records callback cadence only and is never labeled as presented frames or FPS.

## Harness Reliability Fix

The apparent requirement to move the mouse was not a scroll-start dependency. Sampling showed the UI test runner blocked in `open()` while reading or writing files under the repository in `~/Documents`; manual mouse movement only coincided with macOS file coordination releasing that operation.

Performance inputs and in-progress outputs now live under `/tmp`, with completed JSON copied back to repository logs after `xcodebuild` succeeds. Unit-test fixtures and bundled JavaScript are loaded from the test bundle rather than runtime `#filePath` repository paths. A minimal start notification is posted after app launch, and the app resolves the production table/outline scroll view before driving it. No retry/watchdog state machine or manual activation step is required.
