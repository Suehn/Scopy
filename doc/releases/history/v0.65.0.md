# v0.65.0

## Summary

This release adds direction-aware hover intent between a history row and its active preview popover, hardens scrolling with passive rows plus lazily owned interaction state, removes the trace-selected Markdown menu scan from repeated row-body work, makes storage byte accounting lossless across filesystem metadata and SQLite, and makes release tag authority explicit. The preview remains stable while the pointer deliberately crosses the gap, idle rows avoid preview/export/optimization object fan-out, legitimate files above 2 GiB no longer crash or corrupt cleanup accounting, and release-document pushes can no longer publish by themselves.

The release line resumes at `v0.65.0` because Homebrew compares numeric version components and therefore considers historical `0.64` newer than `0.8.8`. Publishing `v0.8.9` would still look like a downgrade to users on `0.64`.

## Key Changes

### Preview Interaction

- Adds a pure safe-triangle policy for popovers on any side or diagonal, including negative multi-display coordinates and live target movement or resize.
- Retains an open preview only while the pointer remains inside the directional corridor and continues making progress toward the target.
- Dismisses on invalid geometry, target loss, movement outside the corridor, reverse movement beyond tolerance, a progress stall, or a hard `500ms` deadline.
- Keeps popover-to-row transfer on a small fixed `120ms` grace and reuses the already-open preview when the pointer returns to its row.
- Adds list-level transfer ownership so an adjacent row cannot steal or dismiss the active preview while the pointer is legitimately crossing to it.

### Lifecycle And Performance

- Uses one cancellable `@MainActor` sampling task only during row-to-popover transfer, at approximately `60Hz` and for no longer than `500ms`.
- Keeps pointer samples outside observable state, so sampling never invalidates SwiftUI views.
- Caches safe-triangle geometry until the popover frame changes; the per-sample hot path performs no collection allocation or trigonometric reconstruction.
- Tracks the active popover window in screen coordinates and accepts frame callbacks only when preview kind and token still match.
- Cancels transfer ownership and sampling on re-entry, target arrival, preview replacement, scrolling, system close, explicit dismissal, invalidation, and row teardown, including a finish-once fallback when the controller is deallocated directly.

### Passive Rows And Scroll Coordination

- Replaces three eager row controllers with one optional interaction session that exists only while interaction or owned asynchronous work is active.
- Replaces visible-row scroll observers with one tokenized active slot and one suppressed-hover candidate, including stationary-pointer restoration after scroll cooldown.
- Uses explicit same-ID content revisions across preview, note, export, optimization, presentation, and cache boundaries so stale work cannot commit against replaced content.
- Restricts pointer suppression to actionable vertical or horizontal scroller parts; ordinary row, button, context-menu, and popover clicks remain transparent.
- Centralizes bounded presentation and relative-time caching, with list-level time updates paused while scrolling or hidden.
- Caches the Markdown context-menu fast signal separately from exact PNG-export capability by content revision, including negative results, with deduplicated utility-priority prewarm and generation-safe invalidation.

### Storage Safety

- Corrects the shared Swift `Int` SQLite adapter to use `sqlite3_bind_int64` and `sqlite3_column_int64`, preserving all current callers without per-column exceptions.
- Keeps the existing SQLite `INTEGER` schema, `PRAGMA user_version = 7`, DTO/protocol types, cleanup budgets, and presentation behavior unchanged.
- Uses checked streaming addition for multi-file logical sizes; an unrepresentable aggregate returns `nil` instead of trapping, wrapping, or saturating.
- Proves exact values across statement binding, disk reopen, payload CAS, batch reconciliation, file metadata update, recent/search hydration, display formatting, and cleanup stopping behavior.

### Tests

- Adds deterministic geometry/session coverage for every placement direction, diagonal and negative coordinates, boundaries, delayed or lost targets, movement reversal, stalls, resize, malformed values, and absolute expiry.
- Adds controller lifecycle, hard-timeout, finish-once, coordinator token, and list-level transfer-ownership coverage.
- Adds real mouse-trajectory UI coverage for a `~200ms` progressive corridor crossing, outside-corridor dismissal, and popover-to-row reuse without flicker.
- Adds lifecycle, revision, stale-token, suppressed-hover restoration, scrollbar hit-testing, cache, relative-time, and deterministic metric coverage for the passive-row path.
- Adds a full-domain SQLite integer regression plus disk-backed 5 GiB persistence, sparse-file metadata, aggregate-overflow, stale-snapshot, and cleanup over-selection regressions.

### Build Tooling

- Removes the push-triggered auto-tag workflow. Only the explicit metadata-driven maintainer commands may create a release tag after the applicable build, test, documentation, and scope-specific gates are complete.
- Adds a standard-library workflow policy validator and 14 focused regressions covering renamed workflows, direct and indirect tag commands, non-allowlisted pushes, tag-ref APIs, tag actions, permission escalation, unsafe release triggers, and folded shell scalars.
- Runs documentation, release metadata/policy validation, and focused policy tests in a lightweight ordinary-CI job; all non-release workflows declare top-level read-only repository permissions.
- Keeps `Build and Release` downstream of an existing `v*` tag or explicit dispatch, without changing version resolution, DMG names, release assets, cask synchronization, or Homebrew acceptance.
- Restores Xcode products to DerivedData so app/test bundles no longer share SwiftPM's `.build` directory or inherit its stale signing metadata.
- Makes `deploy.sh` arguments composable (`release --no-launch`), retains an actionable build log on failure, and uses a dedicated DerivedData root for repeatable local deployment.
- Keeps tagged DMG packaging on the same isolated Xcode-build contract while leaving final release artifacts under `.build/`.
- Makes frontend profiles fully automatic by driving the production scroll view from `NSScreen CADisplayLink`, staging runtime inputs and in-progress outputs in `/tmp`, and copying only completed evidence back to repository logs.
- Bundles unit-test fixtures and renderer assets so XCTest does not perform runtime reads through `#filePath` under the Documents-hosted repository.

## Performance Evidence

- Environment: Apple M3 Pro, arm64, macOS 15.7.3 (`24G419`), Xcode 26.1.1 (`17B100`).
- The focused strict-concurrency performance test evaluated `SafeTriangle.contains` 100,000 times in an average of approximately `9.4ms` across five runs, or about `94ns` per call, with `1.617%` relative standard deviation.
- A transfer samples at most about 31 times under the `500ms` hard deadline, so geometry containment contributes only a few microseconds of total CPU work per transfer on the measured host.
- The existing include-hover frontend profile is a broad preview-rendering smoke and does not automate the row-to-popover corridor, so it is not cited as direct safe-triangle evidence. The dedicated release profile instead documents the passive-row fixed workload and the real-snapshot guard.
- A five-pair Release fixed workload passed in AB and BA order with identical observed work on all ten runs. Passive-row medians improved whole-run row-body count by `66.49%`, row-body total time by `61.07%`, main-run-loop total time by `3.77%`, and main-run-loop p95 by `4.94%`. All five pairs improved row-body count, row-body total, and run-loop total; one p95 pair was `+0.38%`, within the `+10%` guard.
- All fixed runs completed without manual mouse movement and reported `NSScreen CADisplayLink` as the callback source. Callback cadence is not presented as FPS.
- A fresh live Release sample selected the follow-on bottleneck: 411 of 457 sampled row-body stacks entered the uncached Markdown menu predicate.
- A second five-pair same-binary AB/BA kept both sides passive and changed only the menu-signal cache. All ten runs completed the same 51,270px observed path with exactly 1,135 row bodies per side; current recorded 1,135 hits with zero measurement misses/uncached scans. Median row-body total improved `92.09%`, main-run-loop total `9.61%`, and main-run-loop p95 `12.93%`, with row-body and run-loop totals improving in every pair.
- Final-source real-snapshot smoke and standard profiles completed against the 7,807-row DB. The single-repeat standard guard retained mixed signals, including a `+5.29%` text-biased main-run-loop p95 and a volatile thumbnail outlier. An earlier three-repeat full guard against 7,794 rows likewise had two improving and one regressing text-biased p95 pair. Both composite artifacts are recorded as regression observations, not causal pass claims. The storage adapter is a correctness fix, so no speedup is claimed from its fresh backend benchmark. Full frontend details are in [v0.65.0 Frontend Scroll Profile](../../perf/release-profiles/v0.65.0-profile.md).
