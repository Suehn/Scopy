# v0.77.1

## Summary

`v0.77.1` tightens the mouse-wheel scroll detection introduced in `v0.77.0` and records the test gates that were still running when `v0.77.0` was tagged. Clip-view movement now starts a scroll only while a scroll-wheel event is current, so layout-driven movement (thumbnail heights settling, initial load) is no longer mistaken for user scrolling and cannot briefly suppress hover.

## Why This Release

`v0.77.0` shipped at the maintainer's request before the UI and strict-concurrency runs finished. Reviewing the tap-to-preview UI test showed a mechanism worth closing: any clip-view `boundsDidChange` counted as scrolling for 120 ms plus the 250 ms hover cooldown, and `NSTableView` adjusts the clip origin when rows above the viewport change height. The two UI tests that failed in that run also fail on `v0.76.0` (verified in a clean worktree), so they are pre-existing and unrelated.

## Key Changes

- `ListLiveScrollObserverView.ObserverView.isScrollWheelInputCurrent`: a bounds change starts a scroll only if `NSApp.currentEvent` is a scroll-wheel event less than 0.3 s old, or a live-scroll gesture is already in progress; an ongoing scroll is still extended by any movement (smooth-scroll frames, momentum tail).
- Unit test `testClipViewMovementWithoutScrollWheelInputIsLayoutNotScrolling`.

## Verification And Performance

Performance is that of `v0.77.0` (`doc/perf/release-profiles/v0.77.0-profile.md`); the gate changes when a scroll starts, not what a scroll costs. Final steady-state runs on the `v0.77.0` code, real wheel input, 12 s: mouse-like CPU `2.79-2.87 s`, main thread `2.59-2.65 s` (22%); trackpad-like CPU `2.71-2.77 s`, main thread `2.40-2.48 s` (20-21%); callback p95 `8.3 ms`; max `16.7 ms` in five of six runs, one run showed a single `83 ms` callback that was not attributed.

Gates:

- `make test-unit` on the `v0.77.0` source: 790 executed, 3 skipped, 0 failures. Observer and fan-out tests with the gate: 19 executed, 0 failures.
- `make test-strict` on the `v0.77.0` source: 790 executed, 3 skipped, 0 failures.
- UI subset (`HistoryListUITests`, `HistoryListRetainedInteractionUITests`, `HistoryItemViewUITests`, `KeyboardNavigationUITests`, `ListLiveScrollObserverIntegrationUITests`): 29 passed, 3 failed; `testHoverPreviewSafeTriangleKeepsPopoverOpenAcrossGap` passed on rerun (pointer-synthesis flake), `testHoverPreviewDismissesOnScroll` and `testSearchEvidenceExplainsMultipleDistantMatches` fail identically on `v0.76.0` (pre-existing).
- `make docs-validate`, `make release-validate`, `make test-release-policy`: passed.
- TSan, snapshot, backend performance gates: not run, no search, cleanup, or storage code changed.

## Current Status

Same user-visible behaviour as `v0.77.0`; hover after a layout-driven list adjustment is no longer delayed.
