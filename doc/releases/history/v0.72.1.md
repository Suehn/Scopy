# v0.72.1

## Summary

`v0.72.1` fixes the three user-visible defects of the v0.72.0 link-enrichment experience — repeated re-renders, presentation weaker than the official cards, and links occasionally mis-promoted — by removing three real re-render root causes, reworking degraded-link presentation into the official news-card language, and tightening promotion so authored link text always stays a link.

## Key Changes

### Re-render Root Causes Removed

- An empty enrichment sidecar now shares the `"plain"` fingerprint with the no-sidecar world, so a visually identical document can never be forced to rebuild just because a fetch found nothing.
- The enrichment-landed notification no longer covers visible content with the readiness shield; it only bumps the render revision, the old document stays visible, and the swap happens once when the enriched document is ready. The shield mounts only when there is genuinely nothing to show (`!isLiveRender && !isPendingActiveScale`).
- Swift candidate extraction unescapes markdown backslash escapes in destinations (ChatGPT copies write `\&` in query strings), so fetcher keys match the mdast-decoded URLs instead of perpetually "partially hitting" and re-triggering fetch + re-render. Labels longer than 64 scalars are skipped.
- The render output shape changed, so `rendererVersion` bumps v6 → v7 and stale persisted metrics can no longer apply old card geometry.

### Official News-Card Presentation

- A lone enriched article link now renders one wide horizontal news card (favicon + source line, title, two-line snippet) instead of a `web_results` list row. With a thumbnail the image sits in a 144px column after the text; without one the card is text-only — no gray placeholder hole.
- Track cards missing an image render a centered neutral placeholder media slot (`--scopy-rich-media-bg` + Phosphor image glyph) so track geometry stays uniform instead of collapsing.
- Fetched titles/descriptions decode named plus numeric HTML entities at freeze time (`&#8217;` and friends no longer leak onto card faces); malformed or out-of-range references stay literal.

### Precise Promotion Gates

- A bare-link run or list is promoted only when the visible labels are degradation artifacts: all identical, or each equal to its link's source/host name.
- A lone bare link is promoted only when its label is URL-ish, source-ish, or holds a ≥8-character prefix relation with the fetched title. Authored descriptive link text always stays an ordinary link (negative cases pinned in Node tests).
