# v0.84.0

## Summary

- Rank and highlight fuzzy matches by their contiguous phrase, and score fuzzy subsequence queries up to 2x faster

## Key Changes

- **Fuzzy highlight:** a fuzzy match shows the term's contiguous occurrence when that is the better match. Previously it showed the first scattered characters. Searching `原文错了嘛` now highlights "…是**原文错了嘛**" instead of "推导和**原文**有冲突？是原文**错了嘛**". An ASCII fuzzy query also explains a hit inside a decomposed character, such as `cafe` in `Café` written as `e` plus a combining accent.
- **Fuzzy ranking:** a fuzzy-mode query, or a fuzzy+ non-ASCII word, of three or more characters scores the better of two matches: its leftmost scattered match and its first contiguous occurrence. The highlight is the match that was scored.
  - The set of hits is unchanged; only relevance order moves.
  - The row above scores 26 instead of 19.
  - On the benchmark snapshot, 1 of 13 `原文错了嘛` rows, 41 of 1,391 `这个问题` rows, 13 of 6,063 `cmd` rows and 16 of 5,485 `abc` rows now score higher.
- **Faster subsequence scoring:** the scorer reads the text's UTF-8 directly.
  - A character that is a single plain scalar (ASCII, CJK, kana, Hangul syllables and most symbols) and is followed by another such scalar is compared as that scalar.
  - Every other character is still compared with `Character` equality, so canonical equivalence is unchanged.
  - An ASCII term jumps between matching bytes with `memchr`.
- **Development:** native tests went from 760 to 770. They include exhaustive and randomized differential tests that tie the score and the highlight to their definitions.

## Performance

- Release ScopyBench at the engine layer, which also builds each page's highlights. `v0.83.0` (`4a8d1ed`) was measured against this release's code (`ff93c4a`) on a 16,778-row real snapshot.
  - Each binary ran on its own APFS clone, with `--force-full-fuzzy --reset-query q`.
  - Each workload ran 3 A/A pairs, then 5 interleaved A-B-B-A groups.
  - Figures are means of run medians. On each changed workload, every v0.84.0 run beat every v0.83.0 run.

| Workload | v0.83.0 | v0.84.0 | A/A spread |
| --- | --- | --- | --- |
| fuzzy+ `这个问题`, relevance | 151.1 ms | 70.0 ms | 2.0 ms |
| fuzzy+ `原文错了嘛`, relevance | 20.6 ms | 15.6 ms | 0.37 ms |
| fuzzy+ `原文错了嘛`, recent | 20.5 ms | 15.6 ms | 0.40 ms |
| fuzzy `cmd`, relevance | 10.8 ms | 7.1 ms | 0.05 ms |
| fuzzy `abc`, relevance | 9.4 ms | 6.5 ms | 0.15 ms |
| fuzzy+ `数学`, relevance (two characters, unchanged path) | 7.61 ms | 7.59 ms | 0.13 ms |

## Verification

- Release candidate `ff93c4a`. Hardware and toolchain: Apple M3, macOS 27.2, Xcode 27.0 `27A5194q`. The project baselines, Swift 5.9 and macOS 14, are unchanged.
- `make build` and `make test-tooling` pass.
- `make test-unit` (strict concurrency, warnings as errors): 770 tests, 0 failures.
- `make docs-validate`, `make release-validate` and `make test-release-policy` pass.
- Hosted [CI](https://github.com/Suehn/Scopy/actions/runs/39123710894) and [TSan](https://github.com/Suehn/Scopy/actions/runs/39123710997) pass on `ff93c4a`.
- `make test-snapshot-perf-release` on the 16,778-row snapshot (SHA-256 prefix `c8678ffec9638843`), 3 runs. All passed.
  - `cmd` p95: 10.7, 10.6 and 10.6 ms (limit 50).
  - Prepared `cm` p95: 7.8, 8.0 and 7.9 ms (limit 20).
  - Cold `cm`: 64, 65 and 66 ms.
- The highlight change was gated by its own interleaved A/B in [#17](https://github.com/Suehn/Scopy/pull/17), at no measurable cost. The scoring change was gated by [#18](https://github.com/Suehn/Scopy/pull/18) and checked again by an independent rerun. Each PR records the variants that were rejected for cost: contiguous scoring with a `Character` KMP step was 1.4–1.9× slower.
- Each PR also records:
  - a mutation check;
  - a differential over every row of the snapshot;
  - a check that every scalar compared directly is NFC-stable and never joins a neighbouring plain scalar, on the running OS.
- Not run:
  - XCUITest (blocked on this machine);
  - interactive typing latency (`make perf-search-type`);
  - a macOS 14 runtime.
