# v0.65.2

## Summary

`v0.65.2` removes Scopy's project-level Trellis orchestration and replaces it with a lightweight repository-native AI workflow. The previous integration duplicated task state, specs, hooks, commands, and platform adapters across `.trellis`, Codex, Claude, and Cursor, making routine maintenance substantially heavier than the product work required.

This is a tooling-only change. Scopy's product behavior, runtime architecture, performance baseline, build baseline, and deployment contract remain unchanged.

## Key Changes

1. Removes the project-local Trellis runtime, historical task store, workflow state, and generated platform adapters.
2. Removes automatic Trellis context injection and task-lifecycle commands from the Codex, Claude, and Cursor project integrations.
3. Makes `AGENTS.md`, `CLAUDE.md`, and canonical `doc/current` documents the concise sources for repository constraints, implementation guidance, and verification gates.
4. Preserves the independent Scopy Homebrew release skill because it encodes a product-specific operational workflow rather than generic task orchestration.
5. Migrates durable guidance and the active Markdown preview architecture proposal into the normal documentation tree before deleting Trellis-owned copies.

## Core Files

- `AGENTS.md` and `CLAUDE.md`: lightweight AI workflow and repository guardrails.
- `.codex`, `.claude`, and `.cursor`: removal of Trellis-specific hooks, commands, agents, and skills while retaining any non-Trellis project configuration.
- `.trellis`: removed project runtime, specs, task records, and generated workflow state.
- `doc/current` and `doc/proposals`: canonical homes for retained engineering guidance and active design work.
- `.agents/skills/scopy-release-homebrew`: retained standalone Scopy release workflow.
