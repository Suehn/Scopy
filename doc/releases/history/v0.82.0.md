# v0.82.0

## Summary

`v0.82.0` fixes the jump the history list made when a fast scroll ended, adds undo for deletions, ⌘1–9 copying, a status-item menu, Launch at Login and a Simplified Chinese interface, and consolidates the internals that the 2026-09-24 whole-repository review found hard to maintain: the search engine, the clipboard monitor and the Markdown rendering chain. The branch is 113 commits over `v0.81.0`, 398 files, +28,659 / −30,735 lines; 120 files were deleted and 78 added.

## Why This Release

The two-day review (`doc/proposals/review-roadmap-2026-09-24.md`) found the code correct but expensive to change: `SearchEngineImpl` held 3,546 lines with every SQL path, ranking and index lifecycle inline, `ClipboardMonitor` held 2,728, the strict build tolerated 110 warnings, 82 compatibility symlinks and eleven runtime performance flags remained, and several user-facing failures (a failed search shown as "No results", ⌥⌫ deleting the item while a note was being edited, a second instance sharing the database) had no test. Meanwhile the list had jumped at the end of a fast scroll since `v0.80.1`.

## Key Changes

### Fixed

- The history list no longer jumps when a fast scroll ends. Bisected on device to `456abdf` (`v0.80.1`), which removed the explicit `.id(item.id)` from the rows inside `ForEach` as redundant; without it the List's NSTableView drops its measured row heights on every update and re-tiles from the estimate, so a page landing during the momentum moved the content under the viewport. The identity is back and the development guide records why.
- A failed search, history load or page fetch keeps the rows on screen and offers a retry in the footer instead of showing "No results"; pin, delete, clear, AirDrop and Reveal failures are visible.
- ⌥⌫ no longer deletes the item while its note is being edited; keyboard navigation, ⏎ and ⌥⌫ follow the displayed order and skip a collapsed pinned section.
- Hover moves the selection only after the pointer really moved; a keyboard selection is not taken back by rows scrolling under a resting pointer.
- A second Scopy instance fails to start with a visible message instead of sharing the storage root (`flock` on the root).
- Capture evaluates each pasteboard change once, retries a failed write from the cached data instead of dropping the content, replays spooled captures in creation order, and gives TIFF captures their real extension.
- Reading a stored payload no longer fails above 100 MiB; SQLite extended result codes reach the error and the `persistence` log.
- Export cancellation stops the detached capture, encode and pngquant work and releases the concurrency slot only after it exits; a starred `tabular*` environment no longer swallows the rest of the document; a fence may be indented at most three columns; brace-scan limits count characters as before.

### Added

- Undo for a deletion: the row leaves at once, the backend delete is sent after 5 s, and the footer's Undo or ⌘Z restores it in place. Consecutive deletions, paging during the window and undo after the backend's own deletion events are covered by tests.
- ⌘1–9 copies the n-th displayed row with ⏎ semantics; holding ⌘ shows the slot on the first nine rows and the hints follow the displayed order.
- Status-item right-click menu: Open Scopy, Settings…, Check for Updates…, Quit Scopy.
- Launch at Login through `SMAppService`, inside the settings Save/Cancel transaction; a registration awaiting approval keeps the window open and links to Login Items, and the state is re-read when the app becomes active.
- The interface follows the system language in English and Simplified Chinese (`Scopy/Localization/Localizable.xcstrings`, 280 keys); search modes and diagnostic terms stay product terms.
- Export shows its phase (Rendering, Capturing n/m, Compressing, Copying) with a cancel button.
- About folds the performance and ingest metrics into a Diagnostics group; the footer's Load more button is gone (paging is automatic).

### Changed

- Search: `SearchEngineImpl` is 1,510 lines; SQL lives in `SearchReadStore` (row decoding shared with the repository), fuzzy ranking in `FullIndexRanker` and `FuzzyMatcher`, index lifecycles in `FullIndexStore` and `ShortIndexStore` (detached builds; a search awaits the build instead of scanning on the actor and can be cancelled while the build continues), match evidence in `SearchMatchContextBuilder.attach(to:request:)`. `SQLiteSchema.requireCurrentSchema` checks the user version and the five required tables; the optional trigram path, its LIKE fallback, the `data_version` token, the `COUNT(*)` fallbacks and the write-only `schema_version` table are gone. Two hundred recorded SQL cases lock every query path.
- Capture: `ClipboardMonitor` is 671 lines; the read session, capture policy, text extraction, ingest spool, envelope processing, pasteboard writer and metrics are their own types under `Services/Capture`.
- Rendering: one document, `MarkdownHTMLDocumentBuilder.document(source:context:)`, for preview and PNG. The table-pipe, ATX heading and scientific-profile LaTeX repairs (about 1,700 lines of Swift) run in the renderer bundle (`rendererVersion` 13) under an embedded policy; 34 recorded documents reproduce byte for byte. The base CSS is `scopy-document.css` and the runtime is `documentRuntime.js` (`window.ScopyDocument`); the document shell shrinks from about 99 KB to 1.4 KB and its CSP forbids inline script. Export waits for layout through page-side pushes with a time-based fallback when frames stall; a hidden prewarm no longer fails on its paint deadline.
- Storage: `StorageService` is an actor with the cleanup policy passed by value; every commit that advances `mutation_seq` appends exactly one change to `StorageCommitJournal`, which the search engine drains in order and rebuilds only on a gap; cleanup no longer invalidates both indexes.
- Memory: postings are `UInt32`, the full fuzzy index is released after 60 s idle or on memory pressure, the front-end caches release with the panel, memos keep no full text, thumbnails have a byte cap.
- Paging loads 300 rows per page in 50-row chunks (was 100 in 20-row chunks).
- The backend actor is `ClipboardBackend`; app-side names `isSelected`, `rowActivationSurface`, `projectionGeneration`; comments are English throughout.

### Removed

- The eleven `PerfFeatureFlags`, the `Runtime` directory and the warm-profile scheme; 82 compatibility symlinks and the documentation Compatibility section; the repository's five unused search queries and `SearchPlanner`; the raw-HTML `--uitesting` export entry points and their ten UI tests; the mock service and harness views from Release builds; the duplicate `NSLock.withLock`; dead Make targets (`test`, `coverage`, `benchmark`, `test-integration`, `test-perf*`, `test-real-db`, `test-flow*`, `health-check`, `perf-audit`, `perf-warm-scroll-ab`, `perf-unified-table`) and the test classes that only mirrored them.

### Documentation And Gates

- AGENTS.md maps each change scope to its local gate, CI job and extra evidence. The development guide gains code conventions, a glossary, the performance evidence protocol and the local UI verification path; 35 statements that no longer matched the code were corrected.
- `make test-strict` fails on any Swift warning (110 → 0). Performance and verification scripts exit on a missing workload instead of passing.
- Two Codex red-team reviews of the integrated diff produced 32 findings, all fixed before this release.
