# v0.82.2

## Summary

- Harden capture, quit and storage races, page recent history by key, and search non-ASCII text up to 52% faster

## Key Changes

- **Capture:** a pending envelope whose payload is already gone is quarantined and capture continues; it no longer blocks the queue. A quarantine-name collision uses a unique name instead of retrying forever.
- **Quit:** quit waits at most 5 s for pending deletes. Search closes before storage, so the final storage close truncates the WAL (an isolated real-app quit went from a 461,472-byte `-wal` to 0 bytes). A failed delete cancels only a user or updater Quit; logout, restart and shutdown still quit.
- **History list:** the recent list continues from the key of its last row instead of an offset. A change between pages no longer re-reads and replaces every visible row; at 16,000 rows that re-read took 80 ms (p50) and the keyset page takes 2 ms. A new item joining a filtered list counts once, and pagination still reaches the oldest row.
- **Storage:** reservation keys and the containment check resolve the file's directory instead of the file. A file removed mid-call could come back with the `/private/var` spelling, which gave one file two keys and failed the check.
- **Search:** CJK trigram queries use the FTS index again. Substring decisions go through `LoweredTextMatcher`, which decides on UTF-8 bytes only where they provably agree with `String`; a 400,000-text differential fuzz found 0 mismatches. On a 16,690-row real snapshot, single-character non-ASCII queries are 19–52% faster, cold `cm` 24% faster and forced `config` by relevance 71% faster. `co` (+4%) and forced `cmd` by recency (+5%) are about 1 ms slower, because ASCII matches now rank by UTF-16 offsets like the full index.
- **About → Diagnostics:** memory is read through `proc_pid_rusage`, with the same values as before.
- **Development:** CI compiles under Xcode 16 strict concurrency with warnings as errors again. Native tests went from 829 to 742 by removing mock-only and implementation-mirror tests. Tests and ScopyBench no longer leave a preference file in `~/Library/Preferences` per run.

## Verification

- Release candidate `5fb38d7` (Apple M3, macOS 27.2, Xcode 27.0 `27A5194q`; project baselines Swift 5.9 and macOS 14 unchanged).
- `make build` passes. `make test-unit` (strict concurrency, warnings as errors): 742 tests, 0 failures, 0 skips (51.3 s).
- `make test-snapshot-perf-release` on the 16,690-row snapshot (SHA-256 prefix `2724012f0ee77159`): 5 runs; `cmd` p95 15.3–16.6 ms (limit 50); prepared `cm` p95 16.7, 16.8, 17.1, 18.7 and 21.9 ms (limit 20); cold `cm` 85–89 ms after the first run rebuilt the copy's cache (185 ms). The 21.9 ms run failed the gate; right after it another app was using 1.7 cores (load average 7), and the runs before and after it passed. The prepared `cm` margin is thin: baseline `bb9269f` measured 16.2 and 18.3 ms on the same snapshot.
- `make docs-validate`, `make release-validate` and `make test-release-policy` pass.
- Hosted [CI](https://github.com/Suehn/Scopy/actions/runs/39057779920) and [TSan](https://github.com/Suehn/Scopy/actions/runs/39057779924) pass on `5fb38d7`.
- Detailed A/B tables, fuzz evidence and paging measurements are in the release runbook sections dated 2026-10-17 and 2026-10-18. No separate performance profile.
