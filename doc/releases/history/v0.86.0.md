# v0.86.0

## Summary

This release synchronizes history updates, search, and pagination with their database snapshots, preserves an item copied again before its pending deletion commits, and keeps Markdown previews and PNG exports tied to one prepared document. Capture and export retain their resources until the owned work ends. The existing interface, clipboard behavior, settings transactions, and macOS 14 deployment target remain the product contract.

## Changes

- History changes carry the row values, exact removal sets, counts, and versions captured by their write transactions. Search and presentation independently read a bounded commit log; a missing range triggers an authoritative snapshot instead of guessing which changes were lost.
- Recent pages, search results, and index builds use their actual SQLite snapshot versions. UI updates merge by item and covered range, so a newer tail page cannot discard a newer update to the loaded prefix, and a gap does not treat an unrequested pinned preview as deleted.
- Pending deletion checks the copy count in the deleting transaction. A new copy retains and restores the row even when its history notification is delayed or absent from the bounded log; metadata-only updates do not cancel the deletion.
- A clipboard generation with no representations remains pending: a writer may clear and fill the pasteboard without another change-count increment. Late content is captured on the next poll.
- File-size metadata uses the file reference carried by the commit summary; omitted payload bytes no longer reject an otherwise current size result. Image payload replacement retains its stricter byte comparison.
- Capture binds durable replay identity to its prepared payload. Image transforms preserve the original, write a separate owned output, and read back the result before changing its hash and size. Shutdown joins accepted producers and storage work, publishes through the final history position, and closes search before releasing storage ownership.
- Hover previews, pinned windows, and exports carry one prepared document containing its source, render context, identity, and HTML. A later link-enrichment update cannot label older HTML as current; export preserves the captured enrichment even when its layout scale changes.
- Link-enrichment sidecar reads, writes, and pruning run through an actor away from the main thread. Preview body evaluation reads the prepared value instead of performing disk I/O or acquiring the sidecar store's lock. Previews of the same content share a fetch: closing one leaves the others subscribed, and cancellation retains its permit until native network completion.
- Bitmap allocation, fill, scaling, and tile drawing run as sequential background steps. Cancellation keeps the export's resources and concurrency slot until its owned work returns.
- pngquant completion is driven by process termination. Cancellation and timeout request termination, escalate if necessary, and wait for exit before removing temporary files. File compression can produce a separate output while preserving the input.
- Backslash math enters the existing Markdown parser directly instead of being rewritten into dollar delimiters. The same math nodes and KaTeX renderer remain in use; scientific, heading, and table source repairs retain their separate responsibilities. A leading byte-order mark no longer shifts explicit-math lookahead away from the parser's source positions.
- `make run` resolves the app produced by the current Xcode build. The redundant `quick-build` entrypoint is removed, and performance producers and report consumers use explicit callback metrics rather than frame/drop aliases.

## Performance comparison

Release ScopyBench was compared with v0.85.0 on one frozen 10,000-row database (20.9 MB of text; SHA-256 `bfcf282096b49a1f5df2c88f906ddb53dff1b66ec1d4972e68cb53337e2d38fe`). Each workload used three A/A pairs and five ABBA groups; all 84 runs were valid, with six preparation runs excluded by the fixed plan. The machine was an M3 Pro with 36 GB RAM, macOS 15.7.3, and Xcode 26.1.1.

| Metric | v0.85.0 | Candidate | Interpretation |
| --- | ---: | ---: | --- |
| Full-index build phase | 551.383 ms | 551.872 ms | Within measured noise |
| Warm Chinese query, mean of run medians | 22.260 ms | 22.479 ms | Small detectable regression: +0.219 ms, +0.98% |
| Disk-index load phase | 29.518 ms | 29.536 ms | Within measured noise |
| Warm-load process peak RSS, median | 99.906 MiB | 100.750 MiB | Within measured noise |

The query's A/A resolution was 0.206 ms; the A/B ranges did not overlap. The existing Release thresholds passed: service `cmd` p95 was 0.364 ms (limit 50 ms), and prepared engine `cm` p95 was 3.750 ms (limit 20 ms). No new application speedup or memory reduction is claimed. These are backend measurements, not UI latency or app footprint measurements. The comparison used production revision `21b7fde`; the final capture and file-metadata corrections do not change the measured search implementation.

## Acceptance Limits

- The expanded interaction matrix, including global hotkey input and export-cancellation UI, is incomplete. Its unfinished driver is retained locally and is not part of this release.
- A macOS 14 runtime has not been tested. The deployment target remains 14.0; compilation alone is not runtime acceptance.
- Local XCUITest remains blocked by system authentication. Real-app driver results cover only the paths that entered and completed their requested scenes.
- The existing 10 s PDF wait and snapshot fallback remain. A timeout does not prove that WebKit cancelled its native PDF operation.
- The selected warm-query workload has the small regression reported above; no application-wide performance claim is made.
