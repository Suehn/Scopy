# v0.80.6

## Summary

Previews now work as independent reading windows: keep several pinned documents open, hide the history panel after pinning, and continue hovering new items when the list returns. Window resizing reflows and centers Markdown at the selected font scale.

## Key Changes

- Transfer an already-rendered Markdown WebView and model snapshot into each pinned window before releasing the row. Replace only the hover controller; media windows do not retain unnecessary WebViews. Controller identity participates in row equality, and stale ownership leases cannot detach another window.
- Close/reconcile individual windows independently. Re-pinning the same item focuses its existing window. Keep each window's scale, scroll position and frame, constrain restored frames to current displays, and hide history through the normal panel close handler.
- Give hover previews a subtle corner resize grip. Share one quiet toolbar for pin/floating, scale, export and close; brighten controls on hover and remove raw-source titles, duplicate native buttons and content-covering overlays. Drag the fixed window by empty toolbar space; text remains selectable.
- Resolve preview layout from host width divided by the chosen zoom, with a centered 640/768 CSS px reading column and local code/table overflow. Resize updates the existing DOM rather than reparsing or changing cache keys. PNG uses the same canonical renderer and assets with its fixed 816 px output viewport.
