# v0.72.2

## Summary

`v0.72.2` hardens the existing Scopy experience without changing its interaction model: clipboard capture is session-safe, search cancellation and coverage are truthful, history state cannot accept stale snapshots, link enrichment and preview work are bounded, and Settings keeps its explicit Save/Cancel transaction while surviving reopen races. Obsolete profiling and compatibility paths are removed instead of retained behind fallbacks.

## Why This Release

The previous implementation worked end to end, but several failure paths could still surface stale UI state, retain background work longer than intended, or make performance evidence look cleaner than the actual cold/steady-state split. This release closes those concrete gaps while keeping the current UI, settings behavior, renderer chain, search semantics, and clipboard workflow intact.

## Key Changes

### Clipboard Capture And Storage

- Large clipboard envelopes are persisted outside the main actor.
- A monitoring-session identity prevents an old polling task from overwriting a restarted session's pasteboard baseline.
- Deduplication is centralized and file paths use an explicit `file:` identity namespace, so a copied file and equal-looking text cannot collide.
- Real service integration tests prove `saveImages=false`, `saveFiles=false`, polling interval behavior, and cleanup without replacing production services with mocks.

### Search And History State

- SQLite timeout and task cancellation actively call `sqlite3_interrupt`, stopping the query rather than merely abandoning its result.
- Recent exact/regex paths include notes and their match evidence; fuzzy pagination and failure coverage no longer claim complete results when more matches may be unreachable.
- Every initial-load attempt validates the history revision. Two collided snapshots apply nothing and schedule one coalesced trailing load.
- Duplicate load-more calls join one task; semantic event refreshes preserve the visible projection but become `Partial` on failure; selection advances only after a successful delete.
- Production keeps an immediate SQL fallback while the one/two-character index loads. The benchmark now prepares steady state explicitly and records cold fallback separately.

### Bounded Background Work And Security

- Preview and link enrichment share the established bounded permit pool; cancelled queued previews never start, and Markdown enrichment uses structured task ownership.
- Link enrichment caps HTML at 512KiB, images at 8MiB, concurrent work at 2, pending work at 4, and memory/disk entries at 500.
- Initial URLs, redirects, and asset hosts receive public-address preflight. Named hosts resolving only to Clash/Mihomo Fake-IP `198.18.0.0/15` remain usable as routing tokens; literal or mixed private targets remain rejected.
- DNS rebinding between preflight and the actual connection remains an explicit residual boundary; this release does not claim connection-time SSRF proof.

### Settings And Repository Architecture

- Settings keeps explicit Save/Cancel semantics. A session generation prevents an older async save/dismiss from hiding a newly reopened window.
- The About page receives its update action through the coordinator instead of reaching through `AppDelegate.shared`.
- The obsolete runtime performance profiler and its test suite are removed, performance tests live in the performance gate, protocol conformers are explicit, and Debug defaults to the real service unless a test asks for a mock.

- `make build`: passed on the final candidate.
- `make test-unit` and `make test-strict`: 780 executed, 3 skipped, 0 failures each.
- `make test-tsan`: 761 executed, 3 skipped, 0 failures, no sanitizer report.
- `make test-integration`: 15 executed, 0 failures.
- `make test-perf`: 27 executed, 7 heavy-only skips, 0 failures.
- Real 9,566-row snapshot Release gate: service `cmd` p95 `0.682ms` / `50ms`; explicitly prepared engine `cm` p95 `5.458ms` / `20ms`; service cold `cm` observed once at `103.974ms` and is not presented as a percentile or a pass threshold.
- Full frontend profiling was attempted once, but the UI runner timed out while enabling macOS automation mode before the scenario began. No frontend summary or unified table was produced; the result is `environment-blocked`, not passed.
- Detailed claim boundaries and the same-snapshot diagnostic comparison are in the [v0.72.2 performance profile](../../perf/release-profiles/v0.72.2-profile.md).

## Current Status

The user-facing workflow and Settings transaction model are unchanged. Clipboard, search, history, preview, enrichment, and update-window lifecycles now reject stale work at their ownership boundaries, and release performance evidence distinguishes cold fallback from prepared steady state.

## Remaining / Next

- Connection-time DNS rebinding cannot be closed by resolver preflight alone and remains documented as a residual link-enrichment risk.
- First-ever short-query index construction can temporarily use the bounded SQL fallback; only prepared steady state is held to the 20ms short-query gate.
- The frontend full-profile result remains environment-blocked on this host until macOS UI automation can initialize.
- The external Homebrew tap may still require a manual cask sync if the workflow token is unavailable; release completion requires verifying and, if necessary, updating it.
