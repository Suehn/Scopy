# v0.80.1

## Summary

Search pagination now keeps one calibrated result order and mounts new results in small batches, reducing long list updates while retaining the current rows and selection.

## Key Changes

- Fuzzy and Fuzzy+ pagination no longer re-enter the interactive prefilter after full refinement. Previously this mixed two rankings and caused another large replacement on the following page.
- Apply search pages in 20-row batches, publishing complete match evidence with each batch. Query changes and deletion refreshes cancel buffered additions; overlapping pagination requests share one fetch.
- During forced full refinement, keep existing rows mounted while adding new rows, then commit the final ranking atomically. The selected row and visible scroll anchor are not temporarily removed by a truncated prefix.
- Prewarm text and revision caches once per fetched page. Append ID indexes and pinned/unpinned projections incrementally, and update pagination metadata without rebuilding an unchanged result list.
- Include the earlier row-lifecycle optimization: button activation and accessibility remain intact while redundant pointer-region and non-render state updates are avoided.
- Include the separately verified repository cleanup already merged to main: remove unused helpers, track resources and XcodeGen version in project generation, isolate test build directories per worktree, and run tooling self-tests in CI.

## Scope
