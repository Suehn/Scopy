# v0.78.1

## Summary

`v0.78.1` closes two high-priority correctness gaps without changing ordinary clipboard or search interaction: protected pasteboard transactions are never captured, and a valid search hit is no longer discarded merely because its highlight evidence cannot be rendered.

## Key Changes

- `ClipboardMonitor` recognizes `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`, and `com.agilebits.onepassword`. If any item in a pasteboard change carries one of these markers, the monitor advances its change count and skips the whole transaction before extraction or spooling. A following ordinary change is still captured.
- `SearchEngineImpl` treats match evidence as presentation metadata rather than result validity. Per-hit evidence gaps retain the underlying candidate; cancellation still propagates, invalid regular expressions still fail before searching, and the engine records both produced and missing evidence counts.
- `ClipboardService` and `HistoryViewModel` carry evidence-less hits through the existing metadata presentation instead of converting them into a page-wide error.
- The September architecture review records the broader candidate set and the main-thread adjudication. Event-stream lifecycle and termination waiting remain deferred because their complete fixes cross protocol or application-lifecycle boundaries and could affect normal behavior; a proposed Markdown export-slot fix was rejected after reproducing the encoder behavior and finding no baseline defect.

## User-Visible Behavior

Ordinary capture and search presentation are unchanged. Protected pasteboard transactions no longer appear in history. In the rare case where a fuzzy result cannot produce a safe highlight range, the real result remains visible with its normal metadata instead of disappearing or failing the page.

## Follow-up

- Replace the current single-consumer event stream with an explicit subscription API only as a complete lifecycle change, with restart and duplicate-consumer tests.
- If termination durability is changed, use AppKit's delayed-termination contract with idempotent startup handling, an explicit timeout, and Sparkle/quit-path tests rather than a fire-and-forget task.
