# v0.78.2

## Summary

`v0.78.2` keeps every supported marker-bearing clipboard entry as requested, reduces routine history-list I/O by leaving inline payload blobs unloaded until an action needs them, and narrows search-evidence fallback to the individual candidate that failed.

## Key Changes

- `ClipboardMonitor` treats concealed, transient, auto-generated, and 1Password pasteboard types as metadata. Marker-bearing text follows the same capture path as ordinary text; this intentionally supersedes the marker exclusion introduced in the intermediate v0.78.1 release.
- `SQLiteClipboardRepository` uses one summary parser for recent, pinned, and unpinned list queries. These queries preserve identifiers and display metadata but no longer select `raw_data`; the existing item lookup and `loadPayloadData` path provides the full payload on demand.
- `SearchEngineImpl` keeps a candidate when only that candidate cannot produce renderable match evidence. Cancellation still propagates, and query-wide matcher preparation errors still fail the search instead of degrading every result.
- The CI build job now installs the locked Markdown renderer dependencies and runs its full Node contract suite before building Scopy.

## User-Visible Behavior

There is no new setting or interaction. Supported content carrying privacy-oriented pasteboard markers is retained in history, per the product decision to keep all clipboard content. Search rows and history actions look the same; payload-backed actions continue to load the complete item when invoked.

## Follow-up

- Full plain/RTF/HTML snapshot fidelity remains blocked on an explicit data-epoch decision; it will not be implemented through migrations, legacy decoders, or dual-format compatibility paths.
- Event-stream restart semantics and delayed application termination remain deferred until they can be changed and tested as complete lifecycle contracts.
