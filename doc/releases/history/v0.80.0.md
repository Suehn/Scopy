# v0.80.0

## Summary

`v0.80.0` answers a second-party review of the whole repository and adds the pinned preview window. The review's headline finding was real: a clipboard write that failed left the previous clipboard content in place while copy returned normally, so the panel closed over an unchanged clipboard and the Codex path pasted whatever was there before into the frontmost app. Copy is now a reported outcome rather than a best-effort call, a copied folder replays as the folder again, and any hover preview can be promoted to a window you can drag, resize, and keep above other apps while you read it.

## Why This Release

An independent full-repository review of `v0.79.0` was checked line by line against the code. Most of it held up, and it converged on the same conclusion an earlier internal review had reached: the risky part of Scopy is not module structure but a few core contracts that report success without proving it. This release fixes the ones that need no data-model decision, and ships the pinned preview that had been specified but not built.

Two items the review raised stay deliberately unimplemented. Preserving raw copied text and giving each representation its own dedup identity both require a full pasteboard-snapshot payload, and therefore either a migration or an explicit data-epoch reset; neither is authorized, and half-measures such as magic headers, dual reads, or parallel hashes are ruled out. Waiting for `stop()` at quit is likewise still deferred because `terminateLater` changes the quit experience and needs its own startup-race, timeout, idempotence, and Sparkle-relaunch coverage.

## Key Changes

### Copy reports what actually happened

- Every `ClipboardMonitor` write path now throws instead of logging and returning. `ClipboardService` raises `ClipboardCopyError` for a missing row, an unreadable payload, unrenderable image bytes, or a pasteboard that refused the content.
- Usage counts, the item event, panel dismissal, and the synthetic `Control+V` all happen only after a write that reached the pasteboard. A failure keeps the panel open and shows the reason in the footer.

### Faithful file replay

- A file capture replays the exact nodes it recorded, in copy order. Directories and `.app` bundles were filtered out on the way back, so a copied folder silently degraded to its path text and a mixed selection lost its folders. One `LocalFileURLPolicy` now makes that decision in a single place; only size totals and image payloads still require a regular file.

### Pinned preview window

- A pin control on any hover preview promotes it into an independent `NSPanel`: draggable anywhere on any screen, resizable by its edges, floating above other apps by default with a header toggle for an ordinary window level. Position, size, and that preference persist.
- The window holds its own copy of the already-rendered content, so it does not depend on the row's interaction session. List scrolling, row recycling, hovering another row, and closing the history panel all leave it alone; it closes on an explicit action, or when its item is deleted or its payload replaced.
- One preview is pinned at a time and hover previews stop while one is, because a second host would take the single shared Markdown WebView away from it. The hand-over reuses the current navigation instead of re-rendering.
- The preview views now take their layout box from the host, so the same views serve both a fixed popover and a resizable window.

### Correctness and hygiene

- A publication that delivers nothing returns its sequence watermark, so the publications it superseded are not also rejected as stale. Losing both left the UI on an item state the database had already moved past.
- `Scopy/Runtime` was compiled into both `ScopyKit` and the app target, giving `PerfFeatureFlags` two independent copies of its static state.
- `PRAGMA incremental_vacuum` is a no-op on a database that is not in incremental auto-vacuum mode; an oversized WAL now gets the truncating checkpoint that actually reclaims it.
- Text bound with a `-1` length truncated at the first embedded NUL. Binding and reading now use explicit byte counts, taken from the string's own UTF-8 storage so the write path gains no allocation.
- Temporary AirDrop PNGs are swept at startup. A share outlives the sharing sheet, so they cannot be deleted on completion.

## Verification And Performance

Pinned preview verified on the running app through the Accessibility API, because XCUITest cannot start on this machine:

| Check | Result |
| --- | --- |
| Pin produces a separate window | `Pinned Preview` window, content moved into it, popover gone |
| Markdown hand-over does not re-render | `History.Preview.RenderStatus` = `rendered` before and after pinning |
| Resize reflows through the existing path | `420x500` and `980x760`, still `rendered`, window intact |
| Move and resize are available | `AXPosition` / `AXSize` settable and applied; frame restored from autosave on the next pin |
| Always on top, default on | `kCGWindowLayer` `3` -> toggle -> `0` -> toggle -> `3` |
| Explicit close only | Close control removes the window; hover previews and the shared WebView return afterwards |
| Survives the panel session | Window stays up after the history panel closes |

Backend performance, Release build against the real 9,566-row snapshot database:

| Gate | Limit | v0.79.0 | v0.80.0 |
| --- | ---: | ---: | ---: |
| `cmd` p95 (`make test-snapshot-perf-release`) | `50 ms` | `0.526 ms` | `0.546 ms` |
| prepared `cm` p95 | `20 ms` | `4.422 ms` | `4.129 ms` |
| cold `cm` (recorded only) | — | `59.510 ms` | `61.413 ms` |

Gates:

- `make build`: passed, and each of the two commits builds on its own.
- `make test-unit`: 821 executed, 3 skipped, 0 failures (807 at the first commit, 795 in `v0.79.0`; 26 new regression tests).
- `make test-strict`: 821 executed, 3 skipped, 0 failures, no `Sendable` diagnostics.
- `make test-snapshot-perf-release`: passed, table above.
- `make docs-validate`, `make release-validate`: passed.
- TSan: not run. The event-queue change is inside the existing actor and the pinned preview is `@MainActor` throughout.
- XCUITest and `make perf-frontend-profile`: environment-blocked. Both fail with `Timed out while enabling automation mode`, which needs an interactive system-authentication approval this host could not grant; the attempts also wedge `testmanagerd` until it is restarted. `ScopyUITests/HistoryListUITests/testPinnedPreviewSurvivesListScrollAndClosesOnlyExplicitly` is committed and unrun.

The scroll path gains one `Bool` comparison in `HistoryItemView`'s `Equatable` and no new work; the pinned flag reaches rows through the existing `HistoryRowContext` channel and changes only on pin and unpin.

## Current Status

Copying, capture, search, scrolling, and preview behave as before, except that a copy which does not reach the pasteboard now fails visibly instead of silently, and a copied folder pastes as a folder. Pinning a preview is new and entirely opt-in: nothing changes until the pin control is used.

## Remaining / Next

- Raw text preservation and per-representation dedup identity remain blocked on an explicit data-epoch decision. They share one data model and should be done together, in one design cycle.
- Waiting for the asynchronous `stop()` at quit (`terminateLater`) is still deferred; it affects the quit experience and needs its own test coverage.
- The image write path still has no pixel budget and rasterizes on the main actor for non-PNG and paletted-PNG payloads. A small file with huge dimensions can still allocate width x height x 4.
- The release pipeline still builds and publishes without re-running the test gates at the tag SHA, and a missing Sparkle signing key only warns. `main` has no branch protection.
- Search index memory is still never released after the first search of a session, and `SearchEngineImpl` remains one 5,200-line unit.
- The 500 ms poll window still cannot capture two copies made inside it.
