# v0.65.1

## Summary

`v0.65.1` repairs the final delivery boundary without changing product runtime behavior. The public `v0.65.0` workflow built Scopy successfully but its DMG step still copied `.build/Release/Scopy.app`, a path removed when Xcode products were isolated in DerivedData. This release makes GitHub and local tagged packaging consume one packager, one explicit DerivedData contract, and one DMG/SHA output location.

The version is bumped instead of moving `v0.65.0`, preserving tag and asset immutability even though the failed run published no DMG.

## Key Changes

1. Replaces the workflow's duplicated XcodeGen/build/DMG shell with `scripts/build-release.sh`.
2. Sets `SCOPY_XCODE_DERIVED_DATA` to a safe `${{ runner.temp }}/Scopy-Release` path in GitHub Actions.
3. Keeps the built app under DerivedData and the final `Scopy-<version>.dmg` plus `.dmg.sha256` under repository `.build`.
4. Aligns action upload, existing-release checksum download, and SHA resolution with those `.build` artifacts.
5. Adds a release-policy regression that fails if the workflow reintroduces `.build/Release/Scopy.app` or stops using the shared tagged packager.

## Core Files

- `.github/workflows/release.yml`: one shared tagged packaging entrypoint and aligned asset paths.
- `scripts/build-release.sh`: authoritative DerivedData app path plus DMG/SHA sidecar generation.
- `scripts/release/tests/test_validate_workflow_tag_policy.py`: packaging-path drift regression.
- `.trellis/spec/backend/build-release-guidelines.md`: executable local/CI output contract.
- `doc/current/release-runbook.md`: failure evidence, recovery rule, and immutable-tag guidance.
